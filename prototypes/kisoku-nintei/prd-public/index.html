6.01 业务场景设置

蓝色为新增，橙色为修改，红色删除线为废弃规则。

6.01.1 概述

四步向导：Step1 案件集约规则，Step2 工作流画布，Step3 通知设置，Step4 输出字段与发布。新建、编辑已发布、复制场景共用流程。案件场景只展示一个主状态，不展示分步状态。各步骤保存只写草稿配置；只有发布生成正式版本号。

6.01.2 功能点

  1. 场景列表：新建、复制、重命名、删除、关键词检索；复制后进入 Step1 继续编辑。
  2. Step1：配置名称、说明、账票集合（1～20）、主账票与主字段、关联账票字段关系；支持关联检查与 AI 自动关联。AI 根据当前场景配置动态生成关联规则，不使用固定推荐数据。
  3. Step2：进入工作流画布；画布读取 Step1 账票与关系，限制节点可选范围。独立的设置检查执行静态配置校验；不读取测试样例、不调用节点。
  4. Step3：配置全局通知规则模板。每条规则选择対象节点、触发事件、通知对象、件名、内容和可插入变量；页面不展示触发表达式。处理节点按节点专属 Status / Result 自动判断；人工确认按完了、补件、案件中止三出口事件触发。
  5. Step4：从 OCR 抽出账票类型中勾选要导出的字段（允许 0）。点保存固化勾选；0 字段也可以保存，表示用户确认本场景不导出 OCR 字段。
  6. 发布：Step2 设置检查通过后，场景变为可发布。Step3、Step4 只保存通知和输出配置，不参与发布门禁。Step4 点击公开时若不是可发布状态则自动执行同一检查；检查通过后显示确认弹窗，确认后生成新版本号；新案件只读取已发布版本。

废弃：Step2 使用内置样例真实执行工作流，测试成功后才允许发布。

6.01.6 Step1 案件集约规则

Step1 负责业务场景基础信息、关联账票集合、主账票、主字段和账票间字段关系。Step2 的账票候选、OCR 字段候选、条件字段候选和 Step4 的输出候选都从 Step1 派生。

Step1「保存」只写场景基础与集约规则，不生成版本号，不执行业务校验，并停留在 Step1。「次へ」检查必填项、账票数量上限、账票关系网络与后续引用保护；每个账票均可直接或间接到达主账票时，保存并进入 Step2。

Step1 不提供清空按钮，原因是关联账票集合、主账票和业务键可能被 Step2 条件、OCR、AI 检证和 Step4 输出引用。用户需要修改基础信息或案件集约规则时，直接编辑对应字段并保存。

关联预览中的账票默认折叠，仅展示已参与关联关系的字段；未配置字段关系的账票只展示账票标题。点击账票标题可展开全部字段，再次点击恢复折叠。字段关系使用无箭头直线连接两侧具体字段，不表示方向和优先级。

账票间字段关系按帐票对维护。每个 Group 表示一套可独立成立的字段关联方案。一个帐票对至少包含 1 个 Group，并允许继续添加多组；界面按 A、B、C 顺序标识，超过 Z 后使用 AA、AB。A、B、C 只用于界面区分，不表示优先级或执行顺序。

界面以帐票对照矩阵呈现。账票对使用“左侧账票选择框—双向箭头—右侧账票选择框”的单行结构；不显示外部标题，未选择时通过选择框占位符区分左右两侧。两侧只表示配置列位置，不表示主账票或关联账票角色。条件组相对帐票对向右缩进。每条字段关系同样使用“左字段选择框—双向箭头—右字段选择框”的单行结构；不显示外部标题，未选择时通过占位符区分左右字段。每个条件组内的字段关系固定按 AND 判断，只有组内全部字段关系成立，该条件组才匹配成功。同一账票对内，完全相同的左右字段关系只能配置一次，不得在同一 Group 或不同 Group 中重复。

同一帐票对的组间逻辑固定为 OR。每个 Group 独立判断，任一 Group 匹配成功即表示该文件对的字段规则匹配成功；多个 Group 同时匹配成功时仍只产生一条文件对关联。界面在相邻 Group 之间显示只读 OR 标记，并在每个 Group 标题旁显示「グループ内：AND」。

Group 内多条字段关系固定按 AND 判断，只有全部关系成立，该 Group 才匹配成功。每条关系的左右字段均须完整选择；任一侧字段值为空或左右值不相等时，该关系不成立；左右两侧同时为空不得判定为相等。同一账票对内，完全相同的左右字段关系只能配置一次，不得在同一 Group 或不同 Group 中重复；同一字段可以参与不同的字段关系。系统不限制 Group 的字段组合或 Group 之间的包含关系。

AI 自动关联同时评估主账票与关联账票、关联账票与关联账票，不设置账票对优先级。生成结果须使所有已选账票形成连通关系，每个账票至少参与一条关联，但不要求任意两个账票都直接关联。每个账票对只生成 1 个 Group，不自动生成 OR 备用 Group；组内存在多个字段关系时固定按 AND。字段按业务语义和区分度选择，字段名可以不同；涉及主账票时，主字段可作为候选。金额、日期、医疗机构名、诊断名和地址只作为辅助字段。AI 只能返回当前 Step1 已选账票及其抽出字段；返回非法账票、非法字段、重复账票对或空关系时，本次生成失败且不覆盖现有规则。

关联检查只检查一件事：是否存在无法通过账票间关系最终到达主账票的关联账票。系统将账票间关系视为无向图，从主账票开始遍历；关联账票可以直接连接主账票，也可以先连接其他关联账票后间接到达主账票。只有与主账票所在关系网络完全断开的账票才判定为未关联。账票数量、主账票和主字段在添加账票或字段选择时已经校验；关系字段有效性、关系方向、重复关系和后续引用保护不属于关联检查。

6.01.7 Step2 工作流画布

Step2 负责配置工作流节点、连线、条件表达式、人工确认出口和节点参数。Step2 读取 Step1 的账票集合、主账票、关联关系和 OCR 字段；不能在 Step2 单独新增、删除或重命名账票类别和 OCR 字段。

Step2 不提供样例测试入口，提供独立的设置检查。设置检查执行静态配置校验，检查结构、连线、节点必填项、变量引用、字段选择和节点依赖；不读取 Mock 样例、不求值条件路径、不真实调用节点。检查失败时提示首条错误；错误对应节点时选中并定位该节点。保存、下一步和步骤条跳转不触发该检查。

废弃：Step2 测试弹窗使用系统内置案件样例，真实调用处理节点并按命中路径生成执行时间线。

Step2 清空删除开始节点以外的所有工作流节点和连线。开始节点是系统固定入口，默认存在，节点面板不提供新增，用户不能单独删除，也不会出现多个开始节点。リセット 后场景回到草稿。清空后画布仅保留开始节点，用户需要重新添加处理节点、条件节点、人工确认和结束节点，并重新通过设置检查后才能公开。

6.01.8 Step3 通知设置

Step3 负责配置全局通知规则模板，不读取 Step2 画布里的实际节点实例。运行时由工作流节点类型、输出变量和变量取值匹配这里的全局规则；如果 Step2 没有对应节点，则对应规则不会被触发，但配置本身仍可保存。

6.02.2 功能点

  1. 画布编辑：添加/插入/连接/删除节点与连线、自动整列；逻辑变更置测试为未测试。节点标题固定为类型名。
  2. 节点选择器：业务 Agent（前处理、OCR、映射、检证）、控制（条件、人工确认）、扩展（自定义函数）、端点（开始、结束）。
  3. 节点编辑面板：按类型展示参数；底部「出力変数」不折叠，只读展示变量键、日文显示名和右对齐类型；i 中显示取值范围，files[] 额外显示短示例。映射、检证仅跳转设置页。
  4. 变量引用：条件仅选可达上游变量；自定义函数通过「入力変数」追加入参，变量选择器与条件节点一致，并额外允许选择开始节点输出变量。自定义函数不纳入设置检查，脚本及入参问题在运行时记录。
  5. 分支：条件 IF/ELIF/ELSE；人工确认三出口（完了/补件/案件中止），审查者选出口即路由。
  6. 人工确认：默认模板提供 3 个人工确认，分别接在前处理条件、OCR 条件、AI 检证条件的「要确认」分支之后；完了出口回到对应后续主流程；补件出口必须连接人工确认之前的节点并形成回流，不允许连接后续节点；设置检查同时校验是否已连接及回流方向。案件中止出口只在画布上展示，不开放连接。案件中止只结束当前工作流实例，案件后续可重新执行工作流。校验时穿透条件节点检查最近上游处理节点是否为前处理、OCR 抽出或 AI 检证。
  7. 静态校验：Step2 设置检查执行结构、连线、节点配置、变量引用、字段选择与依赖校验。失败时提示首条原因并定位节点；通过后将场景更新为可发布。保存、下一步和步骤条跳转不触发检查。校验不读取样例、不执行节点、不创建人工待办、不发送通知或邮件。
  8. Step1 派生范围：Step2 的账票类别和 OCR 字段只来自 Step1 关联账票集合；Step2 不能新增、删除或重命名账票类别和 OCR 字段。
  9. 说明图标统一为圆形 i。

条件变量规则

条件节点只能选择上游连线可达的 Result、OCR 字段叶子和标准字段叶子。所有节点的 Status 均保留为输出变量，但不得出现在条件变量选择器中。开始节点、结束节点、条件节点本身都不是条件变量来源。条件节点变量选择器不得出现 Array 容器、Date、DateTime、files[]、字段容器 standardFields。

自定义函数节点

节点定位：用户添加输入参数并选择要引用的上游节点变量，在 JavaScript 中通过输入参数名引用。脚本处理结果通过 return 返回，并作为本节点执行结果处理；返回值不注册为可供后续节点引用的输出变量。节点输出变量面板只展示处理状态 codeStatus，取值为 processing / success / failed。

入参规则：

「入力変数」弹窗用于声明脚本会读取哪些上游变量。它不是新建变量池变量，也不是配置出参；自定义函数脚本和入参不纳入设置检查，参照元变化导致的问题在运行时记录。

作用说明
多变量声明文件命名脚本可能同时读取案件 ID、文件列表、账票类型、标准字段、OCR 字段、连番等多项输入，弹窗用于逐条声明这些输入
代码内别名字段级变量显示名可能是日文；配置人员可把参照元绑定成 JavaScript 里的英文变量名，例如 policyNo
依赖处理平台保存每条入参的参照元路径；上游节点、字段或连线变更导致参照元不可达时，运行时按缺失值处理并记录日志
类型提示参照元选定后只读展示类型，帮助配置人员在 JavaScript 里做字符串、数组或枚举处理
  1. 右侧 inspector 的「入力変数」区只展示已添加入参列表；点击「追加」打开入参弹窗。
  2. 入参弹窗填写变量名，并从 Source 下拉选择一个数据来源；不允许手工选择数据类型。
  3. 变量名由配置人员自定义，作为 JavaScript 读取键；同一自定义节点内不可重复。字段级变量的显示名可能是日文，因此允许用英文变量名做代码内参照名。
  4. 添加完成后，入参列表展示变量名和绑定 Source；每条支持编辑和删除。
  5. Source 选择器展示规则与条件变量一致：一级只显示节点名称或账票类型名称，二级只显示裸变量键或字段名，不展示内部节点标识。下拉列表的叶子变量在变量名右侧只读展示数据类型，例如 String、Enum、Array。
  6. 代码内用 inputs.变量名 或 inputs["变量名"] 读取已定义输入变量；例如变量名为 claimFiles 时，用 inputs.claimFiles 读取。变量类型由代码自行判断和转换，平台不在入参弹窗里要求选择类型。

运行规则：自定义函数不参加 Step2 设置检查。运行时按 Source 解析入参值，JavaScript 用 inputs.变量名 或 inputs["变量名"] 读取。空值、缺失值和业务兜底由脚本处理；编译失败、运行异常、超时或返回格式非法时写执行日志，并输出 codeStatus=failed。

脚本示例：文件命名规则

const files = inputs.files || [];

const safe = (value, fallback = "") =>
  String(value ?? fallback)
    .trim()
    .replace(/[\/:*?"<>|\s]+/g, "_");

const timestamp = new Date().toISOString().slice(2, 19).replace(/[-T:]/g, "");
const setNo = safe(inputs.setNo, "001");
const claimNo = safe(inputs.claimNo, inputs.caseId || "00000000-000");
const requestNo = safe(inputs.requestNo, "00000000-000-000");
const docId = safe(inputs.docId, "UNKNOWN");
const branchNo = safe(inputs.branchNo, "00");
const ocrFlag = safe(inputs.ocrFlag, "1");

return files.map((file, index) => {
  const seq = safe(file.sequenceNo, String(index + 1).padStart(4, "0"));
  const ext = file.extension || ".pdf";

  return {
    fileId: file.id,
    fileName:
      `${timestamp}_${seq}_${setNo}_${claimNo}_${requestNo}_${docId}_${branchNo}_${ocrFlag}${ext}`
  };
});
