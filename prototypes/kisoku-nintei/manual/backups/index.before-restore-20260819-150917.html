はじめに

本マニュアルでは、NeosAI IDP の主要機能と基本的な操作手順を説明します。左の目次から章・モジュールへ移動できます。

システム概要

NeosAI IDP は、帳票画像を AI で分類・読取し、業務シーンのワークフローに沿って検証・出力まで進めるプラットフォームです。

ケース例

本マニュアルでは 保険金請求 を通じて、設定から業務操作までを一貫して説明します（説明用の例です）。

  • admin は請求書、診断書、診療明細書、領収書などの帳票タイプを設定し、業務シーン 保険金請求 を公開します。
  • 操作員は同一案件の資料をアップロードし、案件一覧で進捗を確認、マイタスク で人工確認と出力を行います。

ルール設定モジュール

ルール設定モジュール

保険金請求のケースに沿って、推奨順序は モデル → API → マスターデータ → 帳票タイプ → 業務シーン設定 → データマッピング → AI検証設定 です。

各画面への到達順：モデル設定 → API設定 → マスターデータ設定 → 帳票タイプ設定 → 業務シーン設定 → データマッピング設定 → AI検証設定。各機能モジュールの操作手順と、画面だけでは分かりにくい適用タイミングを説明します。ロール詳細は ロール設定 を参照してください。

ルール設定モジュール

モデル設定

LLM への API 接続 と 用途割当 を管理します。帳票タイプの AI 読取や業務シーン公開前に設定します。

操作ポイント

1業務ルール設定 → モデル設定 を開き、API 接続 タブで登録済みの接続を確認します。状態 列で 有効 / 無効 を確認し、操作列の 接続テスト で通信確認できます。新規登録する場合は + 接続を追加 をクリックします。

2接続を追加 画面で プロバイダ、API ベース URL、API キー、モデル名を設定して 保存 します。保存直後は接続情報が登録されただけで、まだ 有効 にはなりません。一覧の 接続テスト を実行し、通信が成功した時点で状態が 有効 になり、そのモデル接続が業務処理で利用可能になります。独自エンドポイントを使う場合は カスタム（OpenAI 互換） を選びます。

3用途割当 タブで、接続テスト 済みで状態が 有効 なモデル接続のみを用途ごとに割り当て、保存します。OCR抽出用途に割り当てたモデルは、帳票タイプ設定 の AI読取設定 で主モデル・検証モデルの候補として表示されます。

ルール設定モジュール

API設定

Open API のエンドポイントと API Key を管理します。通知 URL は 業務シーン設定 の 通知設定 で定義します。

操作ポイント

  1. 業務ルール設定 → API設定 を開きます。
  2. 画面の詳細説明は、別途用意している API 接続文書を参照します。
  3. ここでは API を使う前提だけを確認し、実装や接続手順の詳細は API 文書 側で管理します。
適用ルール API は外部システム連携の入口です。アップロード後の処理は公開済みの 業務シーン設定 に従います。

ルール設定モジュール

マスターデータ設定

表記ゆれをマスター表で管理し、後続の 帳票タイプ設定 の マスタ照合 等から参照します。データ登録後は ベクトル化状態 が 完了 になるまで照合に利用できません。

操作ポイント

1業務ルール設定 → マスターデータ設定 を開き、+ マスター追加 でマスター表を作成します（例：医薬品情報、銀行情報）。

2列設定 — 列名を定義し、照合・検索に使う列は 照会コード を付けます。

3データ登録 — + 項目追加 で 1 行ずつ入力するか、一括インポート でファイル登録します（1 回最大 50,000 行）。

ベクトル化状態の確認 + 項目追加・一括インポート でデータを登録した後は、一覧の ベクトル化状態 を確認してください。状態が 完了 になって初めて、帳票タイプ設定 の マスタ照合（ハイブリッド検索 等）で利用可能になります。待機中・処理中 の行は完了まで待機してください。

1 万行規模以上の大量データでは、ベクトル化に 30 分以上 かかる場合があります。インポート直後に業務設定へ進む場合は、ベクトル化完了を待ってから マスタ照合 の効果テストを行ってください。

状態が 失敗 の行がある場合は、操作列の 再実行 で該当行を手動リトライします。複数行まとめて処理する場合は、一覧上部の ベクトル化再実行 も利用できます。

ルール設定モジュール

帳票タイプ設定

帳票タイプごとに、分類・OCR 抽出・後処理・画像処理・効果テストを 5 ステップで設定します。

操作ポイント

1AI分類設定 — 業務ルール設定 → 帳票タイプ設定 → + タイプ追加 でタイプを作成し、サンプルをアップロードして 説明文 を入力します。同一アップロード内に同類帳票が複数ある場合は、ファイル分割ルール（任意）で切り分け条件を記述します。

2AI読取設定 — + 項目追加 または AI自動生成 で抽出項目を定義し、プロンプト・正解サンプル を設定します。表形式データは テーブル情報読取 タブで列を定義します。設定アイコン → 読取モデル設定 で メインモデル（必須）と 検証モデル（任意）を選びます。

3処理ルール設定 — Step 2 で定義した各項目に 処理ルール（マスタ照合、日付 等）を割り当てます。AIマッチング で項目名からルールを一括提案できます。各項目の 自信度 閾値（初期 95%）もここで設定します。

マスタ照合の設定 参照元は マスターデータ設定 で登録済みのマスター表です。マスタ照合 を選ぶと マスターデータ 下拉が表示され、表名と照合対象列（级联）を指定します。列構成と 照会コード はマスター表側の 列設定 で定義した内容がそのまま使われます。表が未登録の場合は下拉が空となり、保存できません。

照合単位（セル照合 / グループ照合） グループ を空欄にした項目は、当該セル（項目）の OCR 値だけをマスター表に照会します（セル照合）。グループ に同じ番号を入力した複数項目は、OCR 値を組み合わせて 1 回の照合 query として扱います（グループ照合）。例：振込先金融機関名・振込先支店名をともに グループ 1 に設定し、銀行・支店マスタへ同時照合します。

マッチング戦略と返却 画面の マッチング戦略 は固定表示です。ハイブリッド検索 で表記ゆれを許容しつつ類似候補を取得し、コード照会 では 照会コード 列による完全一致も試みます。照合成功時は、命中したマスター行の正規値を当該項目へ書き戻します。類似度が 自信度 閾値を下回る、候補が複数、または未命中の場合は書き戻さず要確認となり、Step 2 読取モデル設定 の人工確認ルールに従い OCR 確認待办が生成されます。

4画像処理設定 — 画像分割対象、組合必須キー／組合任意キー、画像整列対象 を ON/OFF し、キーと閾値を設定します。整列後は 個別 OCR または 結合 OCR を選択します。

5効果テスト — 別版式のサンプルで テスト を実行し、結果を確認します。不足があれば Step 2 の プロンプト を具体化して再調整し、保存 して公開します。

ルール設定モジュール

業務シーン設定

本モジュールでは、帳票タイプ・マスターデータ・データマッピング・AI検証設定を組み合わせ、保険金請求 の実行フローを Step1 案件集約 → Step2 ワークフロー → Step3 通知 → Step4 出力・公開 の 4 ステップで構成します。本マニュアル全体と同一のケースとして、業務シーン名 保険金請求 を公開対象とします。新規・編集・コピーは同一フローです。各ステップの 保存 は下書きのみ更新し、バージョン番号は生成しません。Step2 の 設定チェック 通過後に 公開可能 となり、公開 確認後に正式バージョンが確定します。

保険金請求ケース構成

前章までに設定した帳票タイプ・マスターデータ・データマッピング・AI検証ルールを、次の業務シーン設定に束ねます。操作員側の 新規アップロード・案件一覧・マイタスク は、公開済みのこのシーンを前提に説明します。

設定ブロック保険金請求での設定例参照モジュール
Step1 案件集約 関連帳票：保険金請求書（必須）、診断書（必須）、診療明細書（任意）。主帳票 保険金請求書、業務キー 請求番号。帳票間関連：被保険者氏名、医療機関名、請求金額 ↔ 合計金額 など。 帳票タイプ設定
Step2 ワークフロー 開始 → 前処理 → 条件判断 → OCR 抽出 → 条件判断 → データマッピング → AI 検証 → 条件判断 → 終了。OCR は 3 帳票すべて ON。要確認時は前処理 / OCR / AI 検証それぞれの人工確認へ分岐。 データマッピング設定、AI検証設定
Step3 通知 例：OCR 抽出 · ocrResult = reviewRequired → 操作員、AI 検証 · verifyResult = reviewRequired → 操作管理者、人工確認 · 補件 → 案件担当者。 —
Step4 出力 例：保険金請求書 の被保険者氏名・請求金額・証券番号、診断書 の傷病名・医療機関名、案件 ID・検証結果。 マイタスク エクスポート

操作ポイント

1Step1 — 案件集約ルール：保険金請求 の帳票集合と案件キーを定義します。

1.1 業務ルール設定 → 業務シーン設定 で一覧を開き、＋ 業務シーン追加 で 保険金請求 を作成します（既存シーンは コピー・名称変更・削除、業務シーン名で検索 も利用可）。
1.2 説明に「請求書・診断書・診療明細書を同一案件に集約する標準フロー」などを記載し、+ 帳票追加 で 保険金請求書・診断書・診療明細書 を追加します。主帳票は 保険金請求書、業務キーは 請求番号 を選びます。
1.3 帳票間フィールド関係を設定します。例：Group A で 保険金請求書↔診断書 の 被保険者氏名、Group B で 保険金請求書↔診療明細書 の 請求金額↔合計金額。グループ内 AND・グループ間 OR です。
1.4 関連チェック で 3 帳票すべてが主帳票に到達できることを確認します。未設定が多い場合は AI 自動関連付け で同名フィールドを一括生成し、必要に応じて手修正します。
1.5 保存 は下書きのみ保存し Step1 に留まります。次へ で Step2 へ進みます。

2Step2 — ワークフロー設定：保険金請求の処理チェーンと人工確認分岐を編成します。

2.1 ワークフロー設定 でキャンバスを開き、固定 開始 から 前処理（画像回転・補正・整列）→ OCR 抽出 → データマッピング → AI 検証 → 終了 の主チェーンを配置します。
2.2 OCR 抽出では 保険金請求書・診断書・診療明細書 をすべて ON にします。データマッピング・AI 検証ノードは前章の設定を参照し、モジュール本体は各設定画面で編集します。
2.3 前処理・OCR・AI 検証の各直後に IF/ELSE を置き、*Result = reviewRequired の ELSE 側へ 人工確認（前処理 / OCR / AI 検証）を接続します。補件 出口は上流ノードへループバックします。
2.4 保存 で画布下書きを保存します。設定チェック を実行し、終了ノード到達・分岐接続・OCR/AI モジュール有効化を確認して 公開可能 にします。
2.5 次へ で Step3 へ進みます（設定チェックは自動実行されません）。

3Step3 — 通知設定：保険金請求向けの通知テンプレートを登録します。

3.1 通知ルール追加 で例：OCR 抽出 · ocrResult = reviewRequired · 操作員、AI 検証 · verifyResult = reviewRequired · 操作管理者 を登録します。
3.2 件名・内容に {caseId}、{ocrStatus}、{verifyResult} などを挿入します。トリガー条件は画面に表示されず、対象ノードの Status / Result または人工確認の 完了・補件・案件中止 で判定されます。
3.3 通知ルール一覧 で有効 / 無効を管理します。実行時は Step2 に対応ノードが存在し、イベントに一致した有効ルールのみ送信されます（ノード未配置のルールは保存のみ、実行時は送信されません）。
3.4 保存 後 次へ で Step4 へ進みます。

4Step4 — 出力項目 と 公開：エクスポート項目を確定し、操作員向けに公開します。

4.1 出力項目を設定 で 保険金請求書 から被保険者氏名・請求金額・証券番号、診断書 から傷病名・医療機関名などを選択します。診療明細書の明細列は任意です。
4.2 保存 で出力選択を下書きに固化します。
4.3 公開 をクリックします。公開可能でない場合は Step2 設定チェック を自動実行し、成功後 業務シーンを公開しますか？ を確認して正式バージョンを生成します。公開後、新規アップロード の業務シーン候補に 保険金請求 が表示されます。
ケース連動 本シーンは 帳票タイプ設定 の 3 帳票、データマッピング設定 の標準変数（被保険者名・請求金額など）、AI検証設定 の必要書類・整合性ルールとセットで機能します。Step1 で帳票や業務キーを変更すると Step2 画布と Step4 出力候補が連動し、後続参照がある場合は保存がブロックされます。
適用ルール 各ステップの 保存 は下書きのみ更新し、バージョン番号は生成しません。Step2 設定チェック 通過で 公開可能 になります。Step3・Step4 の保存は公開ゲートに含まれません。Step4 公開 時、公開可能でなければ Step2 設定チェックを自動実行します。公開済みシーンは 現在の下書き と 適用中 バージョンを切り替えて閲覧できます。

ルール設定モジュール

データマッピング設定

本モジュールでは、複数の帳票タイプから抽出された OCR 項目を案件単位の標準変数へ整理します。保険金請求のケースでは、クレーム番号、被保険者名、医療機関名、請求金額などが複数帳票にまたがるため、先に項目の扱いを統一します。

操作ポイント

1業務ルール設定 → データマッピング設定 を開き、マッピングルール生成 で 標準変数・表示名 を入力し、帳票タイプ と フィールド を選んで 標準化ルール を設定して 追加 します。必要に応じて AIルール最適化 を使います。

2マッピング一覧 の 編集 から、複数帳票の ソースフィールド を追加し、値の正規化・同一性判定 を含む 標準化ルール を確認・調整して OK します。

適用ルール データマッピングは、業務シーン設定 の ワークフロー設定 内にある データマッピング ノードで実行されます。項目の競合や業務上の整合性判定は、AI検証ルールで扱います。

ルール設定モジュール

AI検証設定

本モジュールでは、AI検証ルールを設定します。業務ルール設定 → AI検証設定 を開き、6 つの Tab でルールを管理します。適用シーンを先に選んでから帳票タイプ・フィールドを指定する点は、データマッピング設定 と同じです。

操作ポイント

1必須フィールド — ルール一括追加 で 適用シーン、帳票タイプ、フィールド を選び、挿入 で 選択フィールド に追加して 追加 します。標準変数を対象にする場合は 標準フィールド を はい に切り替えます。追加後は ルール一覧 に反映され、行の 削除 で無効化できます。

2必要書類 — 業務シーン を選び、案件に必要な帳票タイプを 必須 または 任意 に設定します。保険金請求では、診断書・保険金請求書・診療明細書などの提出有無を案件単位で確認します。

3標準データ整合性 — データマッピング設定 で参照元が 2 件以上ある標準変数が一覧表示されます。データ整合性検証 スイッチを ON にすると、同一標準変数に紐づく OCR 値の一致を検証します。マッピング自体はデータマッピング設定で編集します。

4テキスト検証 — ルール追加 で 適用シーン、ルール名、ルール記述 を設定します。フィールド参照は 挿入 で {{帳票タイプ.フィールド名}} 形式のトークンを書き込み、少なくとも 1 件の有効なフィールド参照が必要です。必要に応じて AIルール最適化 を使い、ルール一覧 の 編集 で内容を更新します。

5データ検証 — 数値・日付・期間・合計などの構造化データを、算術式または自然文 + フィールドトークンで検証します。入院期間、請求日、点数合計など、帳票間の整合性確認に使います。AIルール最適化 で式の整理も可能です。

6署名・印鑑検証 — 適用シーン、ルール名、対象帳票、検出対象（印影／署名／両方）、必要に応じて 照合先 を設定して 追加 します。各ルールは 状態 スイッチで個別に ON/OFF できます。

適用ルール AI検証ルールは、業務シーン設定 の ワークフロー設定 内にある AI検証 ノードで適用されます。ノードで有効な検証種別のみ実行され、実行時は verifyStatus、verifyResult、逐条ルール結果を出力します。要確認の結果はワークフロー条件に従って マイタスク の AI検証確認待办に起票されます。

業務操作モジュール

業務操作モジュール

公開済みの業務シーン（本マニュアルでは 保険金請求）を前提に、資料アップロードから案件確認、マイタスク での人工確認・出力までを説明します。

業務操作モジュール

新規アップロード

資料アップロードには、案件集約を伴う集約路径（本画面）と、既存案件へ直接追加する直挂路径（補件）があります。

操作ポイント

1集約路径 — サイドバー 新規アップロード で 業務シーン を選び、ファイル選択／フォルダ選択／ZIP 選択 またはドラッグ＆ドロップで追加します（JPG / PNG / TIF / PDF、各 50MB まで）。

1.1アップロード済ファイル 一覧は行単位で勾选できます。一括削除 は勾选した行のみ削除します。分類・案件集約を実行 は一覧内のすべての合格ファイルを対象に、分類 API と案件集約 API を順に実行します（勾选子集のみではありません）。

1.22 つの API 完了後、案件一覧 の 未集約ファイル タブへ遷移します。自動归属できなかったファイルは同タブに残り、再度 分類・案件集約を実行 するか、手動で校准できます。

2直挂路径（補件） — 案件一覧 · 集約済み案件 で案件ステータスが「補件」の行から 補件 を開きます（補件アップロード API も利用可。案件番号は必須）。

2.1弹窗は対象案件番号に绑定され、業務シーン は表示されません。確認アップロード で当該案件に直接書き込み、未集約リストや案件関連処理は経由しません。

2.2形式・50MB 上限・解像度校验とエラーメッセージは集約路径と同じです。集約路径との違い：直挂は案件番号が必要で、集約路径は 業務シーン 選択と分類・案件集約の一連処理が必要です。

業務操作モジュール

案件一覧

本モジュールでは、案件の集約状態、配下ファイル、詳細プレビュー、ワークフロー進捗、操作ダイアログを順に確認します。保険金請求では、集約済み案件 で進行中案件を把握し、展開後のファイル、詳細画面、担当者割当、ファイルの案件変更、未集約ファイルの手動紐付けまでを確認します。

操作ポイント

1集約済み案件 タブで、案件 ID、業務シーン、業務 key、作成日時、更新日時、ファイル数、入力済書類、案件ステータス、担当者を確認します。案件 ID または 詳細 から詳細画面へ進めます。上部の検索条件で絞り込み、すべて展開 で配下ファイルを一括表示できます。

2案件行を展開すると、配下ファイルのファイル名、帳票タイプ、アップロード日時、更新日時、帳票枚数、ファイルサイズ、ファイルステータスを確認できます。各行の プレビュー、案件変更、削除 でファイル単位の操作が可能です。案件行では 詳細、割当、処理中止、削除 が利用できます。

3案件 ID または 詳細 から詳細画面を開き、ファイル一覧 タブで帳票タイプ別のツリーと画像プレビューを確認します。プレビュー上のツールバーで拡大・回転ができ、不要ファイルは 削除 で除去できます。

4ワークフロー明細 タブでは、処理フロー で本案件の経路（実線）と未採用分岐（点線）を確認し、経過ノード で各ノードの開始・完了日時と担当者、ファイル処理明細 でファイル単位の OCR 進捗を確認します。

5案件行の 割当 で 担当者割当 ダイアログを開き、担当者を指定します。処理中止 では、対象案件のワークフローインスタンスを終了し、未完了タスクを無効化します（確認ダイアログで OK）。

6展開後のファイル行で 案件変更 をクリックし、帳票タイプ・関連 key・紐付け先案件を指定して別案件へ移動します。分類失敗などで誤った案件に紐付いたファイルの修正に使います。

7未集約ファイル タブでは、自動集約に失敗したファイル（集約ステータス 紐づけ失敗、失敗理由など）を確認します。案件集約を実行 で再処理するか、手動紐付け で 手動校正 ダイアログを開き、帳票タイプと紐付け先案件を指定します。

業務操作モジュール

マイタスク

ワークフローで生成されたタスクの一覧・実行入口です。OCR 抽出確認、AI 検証確認、エクスポート の 3 種類を扱います（前処理確認タスクは本期対象外）。OCR / AI 検証の実行画面では、ワークフロー上の 人工確認 ノードに対応する OCR 抽出完了・AI 検証完了、補件、案件中止 が出口として連動します。

操作ポイント

1未対応 / 対応済 でタスクを切り替え、タスク種別・案件キー・業務シーン・業務 key で絞り込みます。未対応行の 対応 で実行ページへ進みます。

2OCR 抽出確認 — 帳票画像と抽出結果を対照しながら修正します。

2.1 一覧の 対応 から実行画面を開きます。左に帳票プレビュー、右に テキスト読取 / テーブル情報読取 タブがあります。要確認フィールド数は帳票タブのバッジと右上の 要確認 件数で確認できます。
2.2 テキスト読取 タブで各フィールドの切图と入力値を確認します。項目位置を非表示 を ON にすると、右側にフィールド切图が表示され、入力框をクリックすると左の帳票上で対応領域がハイライトされます（左右連動）。エラー箇所のみ表示・一括確認 で要確認項目を絞り込めます。
2.3 テーブル情報読取 タブで明細行（例：振込先指定口座）を確認・修正します。行単位で 確認待ち 状態を解消します。
2.4 Master 照合フィールドでは、完全一致しない場合に 類似度検索 候補が表示されます。候補を選んで正規値に置き換えます。
人工確認ノードとの連動（OCR / AI 検証共通） 実行画面フッターの OCR 抽出完了 / AI 検証完了 は、ワークフロー画布上の 人工確認 ノードの 完了 出口に対応し、後続ノードへ進みます。補件 は 補件 出口へルーティングされ、画布で設定した前序ノード（例：前処理・OCR 抽出）へ回流します；案件は 補件 状態となり、案件一覧 から追加書類をアップロードします。案件中止 は 案件中止 出口に対応し、現在のワークフローインスタンスを終了します（案件自体は再実行可能）。保存 は進捗のみ保存し、出口は確定しません。

3操作管理者は一覧の 割当 で タスク割当 ダイアログを開き、担当者を変更できます（案件一覧 の案件担当者改派とは独立）。

4AI 検証確認 — 帳票タブまたは AI 検証要約結果 タブで検証結果を確認します。

4.1 完備性 モジュールで 欠損帳票（必要書類の不足）と 欠損フィールド（必須項目の未抽出）を確認します。帳票名・フィールド名をクリックすると該当帳票タブへ移動できます。
4.2 データ検証 でルール式の判定結果と検証フィールドの値を確認します。確認済み / 確認待ち で状態を更新します。
4.3 印鑑・署名検証 で対象帳票・検出対象・照合先フィールドを確認します。帳票名リンクから該当帳票のプレビューへ遷移できます。

5エクスポート — ワークフロー完了後の出力タスクです。エクスポート設定 で定義した項目・条件に沿って内容を確認し、提出して案件を エクスポート済 にします。

システム設定モジュール

システム設定モジュール

ユーザー管理、権限管理、セキュリティ設定 で、アカウント・メニュー権限・データ保存期限を管理します。

システム設定モジュール

ユーザー管理

ユーザーの作成、権限割当、状態管理を行います。

操作ポイント

1システム設定 → ユーザー管理 を開き、+ ユーザー追加 でユーザーを作成します。画面上部の 有効なユーザー で上限（例：1/50）を確認できます。

2既存ユーザーは 無効、編集、パスワードリセット、削除 で管理します。

システム設定モジュール

権限管理

権限テンプレートを作成し、各ロールがアクセスできるメニュー範囲を設定します。

操作ポイント

1システム設定 → 権限管理 を開き、+ 権限追加 で権限テンプレートを作成します。

2一覧の メニュー権限 を開き、付与する機能モジュールを選択して OK で保存します。

システム設定モジュール

セキュリティ設定

データ保存期限とアイドルセッション（自動ログアウト）を設定します。

操作ポイント

1システム設定 → セキュリティ設定 を開きます。

2データ保存期限設定 で読取データの自動削除サイクルを選びます（7 日～12 ヶ月）。期限超過後のデータは復元できません。

3アイドルセッション設定 で 自動ログアウト時間 を選び（15 分～2 時間、または制限なし）、保存 します。
