ADMINISTRATOR GUIDE

配置侧操作指引

对象角色：系统管理员、业务规则配置人员
示例场景：保险金请求（主账票：保险金请求书；关联账票：诊断书、收据与诊疗明细、本人确认文件等）
说明：界面上的必填项、字段类型等以产品界面为准；本手册侧重操作顺序与页面上不易察觉的规则。

1. 模型设置

注册平台使用的 OCR、文档分类、AI 检证、通用 LLM 等模型，执行测试确认连通后再被账票类型引用。

  1. 打开菜单 モデル設定（模型设置）。
  2. 点击 ＋ モデル追加，填写模型名称、种类、提供商、模型 ID、API 密钥等（界面有标注）。
  3. 保存后执行 テスト，确认返回正常。
  4. 为保险金请求场景至少准备：OCR 模型、文档分类模型（若账票分类用 AI）。
页面上看不出的规则 修改已被业务场景引用的模型 ID 可能影响在途案件。变更后请在业务场景 Step2 重新执行 設定チェック。

2. 账票类型设置

为每种账票定义分类方式、OCR 抽出字段、表格列、AI 前处理策略。保险金请求典型账票：保险金请求书、诊断书、收据、诊疗明细、本人确认文件。

  1. 打开 帳票タイプ設定，点击 ＋ 帳票タイプ追加。
  2. 按向导步骤完成：基本信息 → 文档分类（关键词 + AI 模型）→ OCR 字段与表格定义 → AI 前处理选项。
  3. 各账票选择对应的 OCR / 分类模型（来自第 1 步）。
  4. 全部完成后点击 公開；仅已发布账票可被业务场景 Step1 选用。
保险金请求示例 保险金请求书建议抽出：证券番号、请求番号、请求金额、契约者名；诊断书抽出：诊断名、入院期间；收据抽出明细表格（诊疗行为、点数、金额）。
页面上看不出的规则 删除或改名 OCR 字段时，若已被业务场景、数据映射、AI 检证或 Step4 输出引用，系统会阻断保存并提示先解除引用。编辑已发布账票会生成新草稿版本，在途场景继续用旧发布版直到再次发布。

3. 主数据设置

维护 AI 检证「标准数据整合性检查」用的主数据表，如保险契约主数据（证券番号 → 契约者信息）、医疗机构主数据。

  1. 打开 マスタデータ設定。
  2. 新建主数据，指定键字段（如证券番号），通过 CSV 批量导入或 API 连携更新。
  3. 保存后在 AI 检证设置中引用该主数据。
应用节点 主数据本身不在工作流节点执行；在画布AI 检证节点运行时，由检证规则中的「标准数据整合性」模块按键字段 lookup 并比对 OCR / 映射结果。

4. 数据映射设置

定义跨账票统一的标准字段（如 standardFields.policyNo、claimAmount、patientName），并配置各账票 OCR 字段到标准字段的映射与优先级。

  1. 打开 データマッピング設定。
  2. 新增标准字段，再为每个标准字段绑定来源账票 OCR 字段及优先级（例：证券番号优先取保险金请求书，其次诊断书）。
  3. 按需配置转换规则（全半角、去逗号、trim 等）。
  4. 完成后 公開。
页面上看不出的规则 多账票映射到同一标准字段且值冲突时，默认采用优先级最高账票的值；若需将冲突本身标为要确认，须在 AI 检证中另建规则。映射在工作流「数据映射」节点执行，节点引用全局已发布映射配置，Step2 不校验输入数据内容。

5. AI 检证设置

从六大模块（必填字段、必要账票、文本检证、数据检证、标准数据整合性、署名印章）组合规则，设置警告 / 错误及后续动作。

  1. 打开 AI検証設定，启用需要的模块。
  2. 逐条添加规则（例：保险金请求书与诊断书的患者名一致；明细合计与收据金额一致；证券番号存在于契约主数据）。
  3. 设置重要度：警告 → 通常进入人工确认；错误 → 按运营策略补件或异常。
  4. 公開后在业务场景 Step2 的 AI 检证节点中选择该配置。
应用节点 规则在工作流 AI 检证节点执行，输入为 OCR 结果 + 映射后的标准字段。输出 verifyResult=reviewRequired 时，若画布连接了条件分支或人工确认，会生成对应待办。

6. 业务场景设置

将集约规则、工作流、通知、导出字段打包为一个可发布版本。新建场景名示例：「保险金请求 · 医疗险 A 型」。

6-1Step1 案件集约规则

  1. 业务规则配置 → 業務シーン設定 → ＋ 業務シーン追加。
  2. 填写场景名称与说明，添加本场景账票（1～20 种）：保险金请求书（主账票）、诊断书、收据等。
  3. 指定主账票与主字段（业务键，如证券番号 + 请求番号）。
  4. 配置账票间字段关联：如「保险金请求书.证券番号 ↔ 诊断书.证券番号」。可用 AI 自動関連付け 生成初稿。
  5. 执行 関連チェック，确认所有关联账票能到达主账票后 次へ 进入 Step2。
页面上看不出的集约规则
  • 同一账票对内：组内字段关系固定 AND，组间固定 OR；完全相同的字段对不能重复配置。
  • 关联检查只验证关联账票能否通过关系图到达主账票，不校验字段值是否相等（相等性在集约执行时判断）。
  • 左右字段同时为空不算匹配；任一侧为空则该条关系不成立。
  • Step1 保存不跑业务校验；次へ 才校验连通性。集约规则在上传后案件集约阶段应用，不在工作流画布内。

6-2Step2 工作流画布

  1. 打开 ワークフロー設定，从固定「开始」节点拖拽处理节点并连线。
  2. 保险金请求推荐主干：AI 前处理 → OCR 抽出 →（条件：ocrResult=reviewRequired → 人工确认）→ 数据映射 → AI 检证 →（条件：verifyResult=reviewRequired → 人工确认）→ 结束。
  3. 各节点在右侧面板配置：OCR 开启哪些账票、AI 检证引用哪套规则、人工确认的担当角色等。
  4. 人工确认的补件出口必须连回前序节点形成回路；案件中止不连下游。
  5. 完成后点击 設定チェック；通过则场景变为「可发布」，失败则定位首条错误节点。
  6. 次へ 进入 Step3（不自动跑设置检查）。
页面上看不出的规则
  • 设置检查是静态校验（结构、连线、必填、变量引用），不读取样例、不真实调用节点。
  • 保存、下一步、步骤条跳转均不触发设置检查；仅「设置检查」按钮与 Step4「公开」时（非可发布状态）会触发。
  • Step2 清空（リセット）删除除开始节点外全部节点，场景回草稿，Step4 需重新保存。
  • 案件启动时绑定当时已发布的工作流版本；发布后新案件用新版本，在途案件不追溯。

6-3Step3 通知设置

  1. 按「对象节点 + 触发事件 + 通知对象 + 件名/正文」追加规则（可在正文插入 {caseId}、{ocrStatus} 等变量）。
  2. 处理节点示例：ocrStatus=failed、ocrResult=reviewRequired；人工确认：完了 / 补件 / 案件中止。
  3. 保存 后 次へ；通知为空也可继续。
页面上看不出的规则 Step3 是全局通知模板，不读取 Step2 当前画布实例。运行时仅当 Step2 存在对应类型节点且事件匹配时才发送；配置了但画布无该节点 → 规则静默不触发、不报错。Step3 不参与发布门禁。

6-4Step4 输出字段与发布

  1. 侧栏选择 Step2 中已开启 OCR 的账票，勾选需导出的 OCR 字段与表格列（允许 0 项）。
  2. 保存 固化勾选。
  3. 点击 公開：若非「可发布」状态，系统自动跑 Step2 设置检查；失败 Toast 提示并跳转 Step2，成功则弹出公开确认。
  4. 确认后生成版本号，场景变为「已发布」；新上传案件读取此版本。
版本与草稿 已发布场景再次编辑会基于「现在的草稿」；正式案件继续使用「适用中」的发布版直到再次公开。四步各保存只写草稿，不单独升版本；只有公开才生成正式版本号。

7. API 管理

  1. 打开 API管理，发行 API 密钥（只读 / 读写、有效期）。
  2. 可选配置 Webhook：案件完结等事件向外部 URL POST。
  3. 密钥仅创建时完整显示一次，请安全保管。

配置项应用阶段 / 节点说明
账票分类规则案件集约上传后对每个文件判定账票类型，再按 Step1 关联规则归案。
Step1 集约关联案件集约主账票 + 字段关系（组内 AND / 组间 OR）决定哪些文件合成一案。

账票 AI 前处理策略工作流 · AI 前处理节点画像分割（单页多票据裁切）在此执行；与集约阶段的文件分割不同。
账票 OCR 字段模板工作流 · OCR 抽出节点按节点上开启的账票执行抽出。
数据映射（全局）工作流 · 数据映射节点将 OCR 字段汇总为标准字段。
AI 检证（全局）工作流 · AI 检证节点执行已选检证规则集。
条件 / 人工确认工作流画布ocrResult / verifyResult 等变量驱动分支与待办；首条人工确认待办写入案件担当者。
Step3 通知模板各节点运行时事件匹配则发站内信 / 邮件；无匹配节点则不发送。
Step4 输出勾选导出待办工作流完结后，导出任务仅包含已勾选字段。
已发布场景版本上传时选定场景新案件绑定发布版工作流；草稿未公开不影响在途案件。

上线前确认

  • 账票类型、数据映射、AI 检证均为「已发布」；业务场景为「已发布」且 Step2 设置检查已通过。
  • 操作员账号在上传画面能选到「保险金请求」场景。
  • 用一套样本件跑通：上传 → 集约 → 工作流 →（如有）我的任务确认 → 导出。
  • 补件、OCR 要确认、检证要确认场景下待办与 Step3 通知符合预期。
