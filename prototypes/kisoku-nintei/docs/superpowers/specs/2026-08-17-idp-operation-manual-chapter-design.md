# NeosAI IDP 操作手册章节设计

> 定稿日期：2026-08-17
> 目标产物：HTML 操作手册
> 当前语言策略：正文先使用中文；产品菜单、按钮、状态等 UI 文案保留日文原文。内容确认后再整体转日文。

## 1. 目标与范围

本手册面向 NeosAI IDP 的配置人员与业务操作人员，说明从系统基础配置、业务规则配置，到保险金请求案件上传、处理、确认、导出的完整操作路径。

手册不展开到每个字段的必填 / 非必填维度，因为产品界面已有明示。手册重点说明：

- 推荐操作顺序。
- 各功能之间的依赖关系。
- 配置规则在实际案件流程中的应用节点。
- 页面上不易直接看出的运行规则。
- 保险金请求场景下的典型配置和操作案例。

## 2. 信息架构

采用“角色首页 + 两条主线”的结构：

1. 首页：按角色和功能模块分区。
2. Admin 配置指引：按实际推荐配置顺序组织。
3. 业务操作指引：按一笔案件从上传到导出的流程组织。

规则说明不单独作为独立章节，而是嵌入对应的配置或操作章节中。章节末尾可保留轻量的确认清单或规则汇总，用于快速回查。

## 3. 首页章节

首页作为导航入口，而不是营销页。第一屏直接让用户按角色进入：

- 管理员 / 业务规则配置人员。
- 操作员 / 操作管理员。

首页模块分区：

- 基础配置：模型配置、API 管理。
- 业务规则配置：账票类型配置、主数据配置、数据映射配置、AI 检证配置、业务场景配置。
- 业务操作：文件上传、案件列表与详情、我的任务、补件与再处理、导出、通知 / 站内信。

首页需要展示端到端流程：

```text
上传 → 案件集约 → 工作流处理 → 人工确认 → 导出
```

每张功能卡片跳转到对应章节锚点。

## 4. Admin 配置指引

Admin 章节按以下推荐顺序组织：

```text
模型配置 → API 管理 → 账票类型配置 → 主数据配置 → 数据映射配置 → AI 检证配置 → 业务场景配置 → 发布前确认
```

### 4.1 推荐配置顺序

说明为什么先配置模型和 API，再进入业务规则配置：

- 模型配置为账票分类、OCR、AI 检证等能力提供基础。
- API 管理为外部系统连携、Webhook、导出推送等能力提供入口。
- 业务配置依赖模型、API、账票字段、主数据、映射和检证规则。

### 4.2 模型配置

覆盖内容：

- OCR 模型。
- 文档分类模型。
- AI 检证 / LLM 模型。
- 模型连通性测试。

内嵌规则说明：

- 已被账票类型或业务场景引用的模型变更，可能影响后续新案件。
- 变更模型后建议重新执行业务场景 Step2 的 `設定チェック`。

章节跳转：

- 下一步：API 管理。
- 关联：账票类型配置、AI 检证配置、业务场景 Step2。

### 4.3 API 管理

覆盖内容：

- API Key 发行。
- 权限范围、有效期、密钥保存提醒。
- Webhook / 外部系统连携配置。

内嵌规则说明：

- API Key 仅创建时完整显示一次。
- Webhook 通常在案件完成或导出执行时被触发，实际触发事件以系统配置为准。

章节跳转：

- 下一步：账票类型配置。
- 关联：业务场景 Step4 输出字段与发布、业务操作导出。

### 4.4 账票类型配置

账票类型配置拆为 5 个步骤：

1. Step 1 基本信息。
2. Step 2 文档分类 / 自动分类规则。
3. Step 3 OCR 抽出字段。
4. Step 4 表格 / 明细抽出。
5. Step 5 AI 前处理 / 发布。

保险金请求示例账票：

- 保险金请求书。
- 诊断书。
- 收据。
- 诊疗明细。
- 本人确认文件。

内嵌规则说明：

- 仅已发布账票类型可被业务场景 Step1 选用。
- OCR 字段会成为数据映射、AI 检证、条件分支、Step4 输出字段的候选。
- 已被下游引用的字段删除或改名时，需要先解除引用。
- 已发布账票再次编辑时，应区分草稿与发布版本。

章节跳转：

- 下一步：主数据配置。
- 关联：数据映射配置、AI 检证配置、业务场景 Step1、业务场景 Step4。

### 4.5 主数据配置

覆盖内容：

- 保险契约主数据。
- 医疗机构主数据。
- 键字段设置。
- CSV 导入或 API 连携更新。

内嵌规则说明：

- 主数据本身不在工作流画布中执行。
- 主数据在 `AI検証` 节点中，由“标准数据整合性检证”模块引用并比对。

章节跳转：

- 下一步：数据映射配置。
- 关联：AI 检证配置中的标准数据整合性检证。

### 4.6 数据映射配置

覆盖内容：

- 标准字段定义。
- OCR 字段到标准字段的映射。
- 多来源优先级。
- 简单转换规则，如 trim、全半角、去逗号等。

内嵌规则说明：

- 数据映射配置在工作流 `データマッピング` 节点应用。
- 该节点把 OCR 字段归一成标准字段。
- 多账票映射到同一标准字段且值冲突时，数据映射只按配置规则生成标准字段；如果需要把冲突标为要确认，应在 AI 检证中配置规则。

章节跳转：

- 下一步：AI 检证配置。
- 关联：业务场景 Step2 的数据映射节点、AI 检证配置。

### 4.7 AI 检证配置

AI 检证配置拆成 6 个模块：

1. 必填字段检证。
2. 必要账票检证。
3. 文本检证。
4. 数据检证。
5. 标准数据整合性检证。
6. 署名 / 印章检证。

保险金请求示例：

- 必填字段检证：保险金请求书的证券番号、请求金额、契约者名。
- 必要账票检证：诊断书、收据、诊疗明细是否齐全。
- 文本检证：诊断内容是否包含特定关键字或除外条件。
- 数据检证：收据金额与诊疗明细合计是否一致。
- 标准数据整合性检证：证券番号是否存在于契约主数据，契约者名是否一致。
- 署名 / 印章检证：请求书是否存在署名或押印。

内嵌规则说明：

- 6 个模块在业务场景 Step2 的 `AI検証` 节点执行。
- 工作流节点侧只引用配置和启用模块，不在节点中重新定义全部规则。
- 输入来自 OCR 结果、数据映射后的标准字段、主数据等。
- `verifyResult=reviewRequired` 时，后续条件分支可进入人工确认。

章节跳转：

- 下一步：业务场景配置。
- 关联：主数据配置、数据映射配置、业务操作 AI 检证确认。

### 4.8 业务场景配置

业务场景配置保留四步向导：

1. Step1 案件集约。
2. Step2 工作流画布。
3. Step3 通知设置。
4. Step4 输出字段与发布。

#### Step1 案件集约

覆盖内容：

- 场景名称与说明。
- 账票集合。
- 主账票与主字段。
- 账票间字段关联。
- `AI 自動関連付け`。
- `関連チェック`。

内嵌规则说明：

- 组内固定 AND，组间固定 OR。
- 左右字段同时为空不视为匹配。
- 关联检查只验证关联账票能否到达主账票，不校验字段值是否真实相等。
- Step1 规则在上传后的案件集约阶段应用，不在工作流画布内应用。

#### Step2 工作流画布

保险金请求推荐主干：

```text
開始 → AI前処理 → OCR抽出 → 条件判断 → 人工確認 → データマッピング → AI検証 → 条件判断 → 人工確認 → 終了
```

覆盖内容：

- AI 前处理节点。
- OCR 抽出节点。
- 条件判断节点。
- 人工确认节点。
- 数据映射节点。
- AI 检证节点。
- 结束节点。
- `設定チェック`。

内嵌规则说明：

- `設定チェック` 是静态校验，不读取样例数据，不真实调用 OCR、AI 检证或数据映射。
- 保存、下一步、步骤条跳转不自动执行设置检查。
- Step4 点击 `公開` 时，如果当前不是可发布状态，会自动执行同一检查。
- 补件出口必须回流到前序节点；案件中止出口不连下游。
- 新案件绑定上传时选择的已发布业务场景版本，在途案件不追溯使用后续新版本。

#### Step3 通知设置

覆盖内容：

- 通知对象。
- 触发事件。
- 件名、正文、变量插入。
- 启用 / 停用通知规则。

内嵌规则说明：

- Step3 是全局通知模板，不读取 Step2 当前画布实例。
- 运行时只有当工作流中存在对应节点且事件匹配时才触发。
- 配置了通知但画布无对应节点时，不触发、不报错。

#### Step4 输出字段与发布

覆盖内容：

- 从已开启 OCR 的账票中选择导出字段。
- 保存输出字段。
- 点击 `公開`。
- 版本生成。

内嵌规则说明：

- 输出字段候选来自 Step2 中已开启 OCR 抽出的账票类型。
- 允许保存 0 个输出字段。
- Step4 只保存输出字段，不参与发布门禁；发布门禁来自 Step2 设置检查。
- 只有 `公開` 才生成正式版本号。

章节跳转：

- 下一步：发布前确认。
- 关联：业务操作上传、案件处理、导出、通知。

### 4.9 发布前确认清单

建议检查项：

- 模型配置已保存并测试通过。
- API Key / Webhook 配置符合连携要求。
- 账票类型均已发布。
- 主数据已导入并设置键字段。
- 数据映射已发布。
- AI 检证 6 个模块按业务需要启用并发布。
- 业务场景 Step1 关联检查通过。
- 业务场景 Step2 设置检查通过。
- Step3 通知规则已确认。
- Step4 输出字段已保存。
- 业务场景已公开。
- 操作员账号能在上传页面选择该业务场景。
- 用保险金请求样本跑通上传、案件集约、工作流、人工确认和导出。

## 5. 业务操作指引

业务操作章节按“一笔保险金请求案件从上传到导出”的流程组织。

### 5.1 一案全流程

```text
文件上传 → 案件集约 → 自动工作流处理 → 我的任务确认 → 导出 → 完了
```

说明人工介入点：

- 上传由操作员触发。
- 案件集约、前处理、OCR、数据映射、AI 检证大多自动执行。
- 当 OCR 或 AI 检证结果需要确认，或工作流配置了人工确认节点时，进入 `マイタスク`。
- 工作流结束后生成导出任务。

### 5.2 文件上传

覆盖内容：

- 进入 `新規アップロード`。
- 选择已发布业务场景。
- 上传 PDF / 图片 / 文件夹。
- 上传完成后自动进入案件集约。

内嵌规则说明：

- 只有已发布业务场景会出现在下拉列表。
- 上传后业务场景不可更改。
- 低于 200dpi 的文件在上传时拒绝，不属于 AI 前处理节点。
- 文件数量、大小、页数限制以界面提示为准。

反向跳转：

- 看不到业务场景：跳到业务场景 Step4 输出字段与发布。
- 上传失败：跳到上传规则说明。

### 5.3 案件列表与详情

覆盖内容：

- 案件检索。
- 案件状态。
- 节点进度。
- 文件列表。
- 未关联文件。
- 操作管理员的中止、再执行、改派等入口。

内嵌规则说明：

- 案件状态是平台聚合状态，不是单个工作流节点变量。
- 文件级状态与案件级状态分层展示。
- 首条人工确认待办生成后写入案件担当者。

反向跳转：

- 案件无法集约：跳到业务场景 Step1 案件集约。
- 状态长时间停留处理中：跳到常见异常处理。

### 5.4 我的任务

拆分为：

- OCR 抽出确认。
- AI 检证确认。
- 人工确认出口：`完了` / `補件` / `案件中止`。

内嵌规则说明：

- OCR 抽出确认通常来自 `ocrResult=reviewRequired`。
- AI 检证确认来自 `verifyResult=reviewRequired`。
- 人工确认节点本身不判断业务是否要确认，只把人工处理结果转换为工作流出口。

反向跳转：

- OCR 字段缺失：跳到账票类型 Step3 OCR 抽出字段。
- AI 检证规则不合理：跳到 AI 检证配置。
- 待办担当不对：跳到业务场景 Step2 人工确认节点。

### 5.5 补件与再处理

覆盖内容：

- 在人工确认中选择 `補件`。
- 案件进入补件状态。
- 追加文件。
- 补件出口回流到前序节点重新处理。

内嵌规则说明：

- 补件出口必须在工作流配置中连接回前序节点。
- 补件后是否重跑 OCR、数据映射、AI 检证，取决于画布回流位置。

反向跳转：

- 补件后没有继续处理：跳到业务场景 Step2 工作流画布。

### 5.6 导出

覆盖内容：

- 进入 `マイタスク` 的导出任务。
- 预览输出字段。
- 执行导出。
- 下载或连携下游系统。

内嵌规则说明：

- 导出字段由业务场景 Step4 决定。
- 操作端不能临时增删字段。
- 工作流未结束不会生成导出任务。

反向跳转：

- 导出字段不对：跳到业务场景 Step4 输出字段与发布。
- 外部连携异常：跳到 API 管理。

### 5.7 通知 / 站内信

覆盖内容：

- 右上角通知入口。
- 通知列表。
- 点击通知跳转案件。

内嵌规则说明：

- 通知来自业务场景 Step3 的通知规则。
- 是否触发取决于运行时节点事件和规则匹配。

反向跳转：

- 未收到通知：跳到业务场景 Step3 通知设置。

### 5.8 常见异常与运营注意点

覆盖内容：

- 上传被拒。
- 案件长时间处理中。
- 应有待办但看不到。
- 导出字段缺失。
- OCR / AI 检证结果异常。
- 误点案件中止后的处理。

同时补充运营注意点：

- 含个人信息文件不得保存到非授权环境。
- 禁止共用账号。
- 非担当案件不应擅自处理。

## 6. 章节互跳规则

全站应支持三类跳转：

1. 首页模块卡片跳转到具体章节锚点。
2. Admin 配置章节底部提供“上一步 / 下一步 / 关联业务操作”。
3. 业务操作章节中的问题说明反向跳转到配置来源。

典型互跳：

| 业务问题 | 跳转目标 |
| --- | --- |
| 上传页看不到业务场景 | 业务场景 Step4 输出字段与发布 |
| 案件无法正确集约 | 业务场景 Step1 案件集约 |
| OCR 字段没有出现 | 账票类型 Step3 OCR 抽出字段 |
| AI 检证结果不符合预期 | AI 检证配置 6 模块 |
| 导出字段缺失或顺序不对 | 业务场景 Step4 输出字段与发布 |
| 通知未发送 | 业务场景 Step3 通知设置 |
| 补件后流程没有继续 | 业务场景 Step2 工作流画布 |
| 外部系统连携异常 | API 管理 |

## 7. 视觉与写法参考

参考 SmartOCR 在线手册的信息表达方式：

- 左侧或顶部目录清晰。
- 页面内有锚点目录。
- 操作步骤使用编号。
- 操作按钮和菜单名在正文中突出显示。
- 注意事项使用提示框。
- 以截图或图示辅助定位页面。

NeosAI IDP 手册风格应保持工作型、清晰、克制：

- 不做营销式 landing page。
- 首页直接提供角色入口和功能模块。
- 章节页面使用固定目录、流程图、步骤块、提示框、表格。
- 卡片和按钮保持小圆角或直角，接近现有 SmartOCR 手册的文档感。
- 正文避免过度解释 UI 字段，重点解释操作顺序和规则生效点。
